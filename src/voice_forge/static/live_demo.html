What's actually happening

On page load this page fetches /v1/audio/voices (the persona + voice catalog) and /v1/backends (the per-backend tunable schemas). The two dropdowns are derived from those: the Persona dropdown is a deduplicated set of human personas, and the Model dropdown is filtered to the backends that actually have a voice registered for the selected persona. The knob panel renders only the inputs that the selected backend's KNOWN_TUNABLES declares — pick Kokoro and you'll see one knob (speed); pick F5 and you'll see six.

On Speak, the page opens a WebSocket to ws://<same-host>/v1/tts/stream and sends a first frame {"voice": "<id>", "sampling": {...overrides...}}. The server merges the overrides into the voice's metadata for this session only — your edits never persist to the registry. Then the text is trickled in (or sent all at once), the server's SentenceBuffer drains complete sentences as they form, runs backend.synthesize() on each, and pushes float32 PCM frames back. The browser appends each frame to a Web Audio scheduling queue so sentences play seamlessly back-to-back.
